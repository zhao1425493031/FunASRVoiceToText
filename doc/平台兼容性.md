# 平台兼容性

## 测试矩阵（HTTP 局域网）

实施环境：Windows 开发、HTTP、`http://<LAN-IP>:8765`、WebSocket `ws://` 同源。

| 平台 | 浏览器 | 页面打开 | 麦克风 | 实时识别 | 备注 |
|------|--------|----------|--------|----------|------|
| Windows | Chrome / Edge | 预期通过 | 预期通过 | 预期通过 | `127.0.0.1` 与 LAN IP 均需实测 |
| Android | Chrome | 预期通过 | 视系统策略 | 预期通过 | 部分 ROM 允许局域网 HTTP 录音 |
| iOS | Safari | 预期通过 | **可能失败** | 依赖麦克风 | Safari 通常要求 HTTPS 才授予非 localhost 麦克风 |
| iOS | Chrome | 预期通过 | **可能失败** | 同上 | 内核仍为 WebKit |

## 技术说明

### ScriptProcessorNode

`web/app.js` 使用 `createScriptProcessor` 进行采集与重采样，该 API 已标记废弃，但在 Android / 旧版 iOS WebKit 上兼容性优于 AudioWorklet。实施计划明确要求采用 ScriptProcessor。

### 安全上下文与麦克风

规范要求 `getUserMedia` 在安全上下文（HTTPS 或 localhost）下使用。本方案采用 **HTTP + 局域网 IP**，因此：

- PC 访问 `http://127.0.0.1:8765` 一般可用。
- 手机访问 `http://192.168.x.x:8765` 可能被拒绝麦克风。

若实测失败，属浏览器策略限制，非服务端缺陷。缓解方向（未纳入本期代码）：自签 HTTPS 或 Tailscale 隧道。

## 复现步骤（麦克风失败时）

1. 电脑运行 `python scripts/run_server.py`。
2. 手机连接同一 WiFi，浏览器打开 `http://<电脑IP>:8765`。
3. 点击「开始识别」。
4. 观察是否弹出麦克风权限；若提示「不安全」或静默失败，记录浏览器版本与系统版本。

## 推荐访问方式

| 场景 | 推荐 |
|------|------|
| 开发调试 | PC `https://127.0.0.1:8765` |
| 手机同网 | **`https://<电脑IP>:8765`** + mkcert 根证书信任（见 [`../README.md`](../README.md) 步骤 12～13） |
| iOS | **必须 HTTPS**，并完成 iPhone 证书信任设置 |

完整安装步骤见 [`../README.md`](../README.md)。

## CLI 回退

浏览器无法录音时，可在 Windows 开发机使用：

```powershell
python -m voicetotext.cli mic
```

不依赖浏览器麦克风策略。
