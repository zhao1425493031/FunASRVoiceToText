# 多人会议 ASR v3 — 方案与背景

> v2（Qwen3 双模型 + Pyannote）已被本方案取代，详见 [v3实施总结.md](./v3实施总结.md)。

## 背景

- v2 使用 FSMN-VAD + Qwen3-0.6B/1.7B + Pyannote Community-1，在 CPU 开发环境内存与依赖偏重。
- v2 相对 v1 的正确演进是 **用 Pyannote 时间轴替代 cam++ 句后聚类**，而非必须用 Qwen 做 ASR。
- 单麦多人场景下，ASR 与说话人分离解耦：Pyannote 通过滑窗 diarization 独立工作，与 ASR 后端无关。
- SenseVoiceSmall 单模型经 FunASR 加载，可显著降低内存占用并移除 `qwen-asr` 依赖。

## 实施目的

1. **轻量化**：移除 Qwen3 双模型与 `qwen-asr`，会议 ASR 改为 SenseVoiceSmall 单模型。
2. **保留单麦多人能力**：继续以 Pyannote Community-1 为唯一说话人时间轴来源。
3. **保留句界质量**：继续以 FSMN-VAD 驱动句界与端点确认。
4. **协议不变**：WebSocket v2 协议字段与行为不变。
5. **代码路径统一**：`device: cpu` 与 `device: cuda` 共用 `MeetingSenseVoiceEngine`。

## 方案与模型分工

| 组件 | 模型 | 分工 |
|------|------|------|
| VAD | fsmn-vad | 语音活动、FSMN 句界端点确认 |
| ASR | iic/SenseVoiceSmall | partial 与 final 共用单模型；定稿可复用 partial 文本草稿 |
| 说话人 | pyannote/speaker-diarization-community-1 | 滑窗 diarization → exclusive 段 |
| 胶水 | FunASR AutoModel | 加载 SenseVoice |

## 与 v2 差异

| 项 | v2 | v3 |
|----|----|-----|
| ASR | Qwen3 0.6B + 1.7B | SenseVoiceSmall 单模型 |
| 依赖 | qwen-asr 必选 | 移除 qwen-asr |
| asr_backend | meeting_qwen | meeting_sensevoice |
| 配置键 | qwen_partial_model / qwen_final_model | asr_model |
| meeting_reuse_partial_for_final | CPU 下 final 复用 partial 模型 | final 复用 partial 文本草稿 |

## 统一架构约束

- `device: cpu`（本地）与 `device: cuda`（服务器）同一套业务代码。
- 语言 `ja` / `zh` 由 `config.meeting.yaml` 默认，客户端 `start.language` 可覆盖。
- 不恢复 cam++；不保留 Qwen 会议路径。
