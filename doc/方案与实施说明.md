# 方案与实施说明

## 背景

在首期 PoC（中文 Paraformer + HTTP/HTTPS Web）基础上，按《企业日语双阶段生产》计划完成：**日语 SenseVoice 嵌入式**与 **FunASR Runtime 2pass 侧车**两阶段，并加入企业加固（鉴权、就绪探针、批处理 API）。

## 实施目的

1. **日语生产**：默认 `iic/SenseVoiceSmall`，`language=ja`，弃用 `ct-punc` 生产路径。
2. **保留 Web 协议**：`/ws/asr` 仍 600ms PCM 块；SenseVoice 侧 2s 窗口累积。
3. **企业运维**：`/ready`、`api_key`、`max_ws_connections`、`funasr==1.3.9`。
4. **可扩展**：`asr_backend=runtime` 时网关转发 FunASR Runtime，同一 Web 入口。
5. **可验收**：`doc/` 企业方案、阶段验收、验收清单与 pytest。

## 最终方案

### 阶段一（sensevoice）

- `asr/factory.py` → `SenseVoiceEngine`：`trust_remote_code`、`rich_transcription_postprocess`。
- `stream_session.py`：按 `stream_window_ms` 累积后 `transcribe_window`；能量 VAD 判句。
- `POST /api/transcribe`：16 kHz 单声道 WAV 批处理。

### 阶段二（runtime）

- `asr/runtime_client.py`：2pass WebSocket 客户端；`map_runtime_to_client` 对齐 partial/final。
- `ws_protocol.RuntimeWSSession`：PCM 转发 + 异步收包。
- `deploy/docker-compose.yml`：先 Runtime 后 gateway。

### 企业加固

- `server/auth.py`：HTTP Header / WS `start.api_key`。
- `config.enterprise.yaml`：生产默认与 Key 占位。
- `web/app.js`：`?key=` 注入 `api_key`。

## 与 PoC 差异

| 项 | PoC | 当前 |
|----|-----|------|
| 模型 | paraformer-zh + ct-punc | SenseVoice ja |
| ASR 结构 | 单文件 asr_engine | asr 包 + factory |
| HTTPS | 后补 mkcert | 默认 certs |
| 鉴权 | 无 | 可选 api_key |
| Runtime | 无 | Docker 侧车可选 |
